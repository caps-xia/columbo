# 下单失败-库存扣减为 0 未拦截

## 现象
用户反馈下单失败，客服转来手机尾号 8888。订单服务近 2 小时 ERROR 日志命中 3 条，均为 `InventoryDeductException: stock=0`。

## 环境
订单交易 / order-service（master 分支）

## 排查过程
1. `countClsLog` 探量：命中集中在 14:00-14:20；
2. `queryClsLog` 按 contextId 拉全链路：入口参数正常，库存服务返回 `stock=0` 但下单流程未前置拦截；
3. `searchCode` 定位 `OrderService.placeOrder`：库存校验在扣减之后才执行。

## 根因
`placeOrder` 先扣库存后校验（校验逻辑晚于扣减调用），库存为 0 时抛出的是底层异常而非业务提示——用户看到"下单失败"，无引导。

## 解决方案
把库存校验前移到扣减之前，`stock<=0` 直接返回业务码 `STOCK_EMPTY`；前端补兜底提示。

## 置信度与依据
高（90%）：日志（3 条 ERROR 链路完整）+ 代码（校验位置与异常类型吻合）双证据闭环。

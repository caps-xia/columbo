# 每日分拣提示词（排查知识库）

> 用法：把下面的提示词整体交给你的 AI 助手（定时任务/手动皆可），把两处 `<知识库根目录>` 换成你的 `troubleshoot.knowledge.root-path` 实际路径（默认 `./data/knowledge`，先把 `docs/llmwiki-template/` 拷过去作为起点）。规矩细节以库内 `AGENTS.md` 为准——AI 会先完整读它。

---

规则文件：`<知识库根目录>/AGENTS.md`（先完整读它，严格按其规矩执行）。

步骤：

1. 列出 `<知识库根目录>/00-Inbox/` 下的速记（`_这个目录怎么用.md` 除外）；若没有待分拣速记，直接结束并一句话汇报"今日无待分拣速记"，不做任何改动。
2. 动手前先查重：读 `index.md` 与 `20-Patterns/` 现有页面，本次速记的可复用套路若已有现成页就更新那页（补链新速记），没有才开新页。
3. 对每条速记按红线复查（密码/密钥/Token/账号口令/连接串不许入库；手机号/身份证/内网域名/真实 IP 脱敏），发现问题先脱敏再归档，并在汇报中指出。
4. 置信度门槛复查（AGENTS.md「置信度门槛」）：速记「置信度与依据」为中/低档（<85%）或标注"疑似/待验证"的，不归档、不提炼 Pattern，移动到 `00-Inbox/_待复核/`（文件名不变），汇报中列出等人工复核。
5. 按业务线判据归类（按问题业务内容，不按环境/系统硬分；判据见 AGENTS.md「归类判据」）。移动用 `mv`（库非 git 仓库），不改文件名（保持 `速记-YYYYMMDD-问题简述.md`）；移动后把 frontmatter 的 `system` 改为目标业务线，缺 frontmatter 的按模板补齐（tags/date/system）。
6. 可复用套路提炼或补链到 `20-Patterns/`：通用坑/通用教训 → `concepts/`；日志查询命令/定位技巧 → `snippets/`。新开的 Pattern 页页首一两句说明讲什么，页尾注明来源（哪天、哪个业务线、来自哪条速记）；双链用 `[[真实文件名]]`，不确定目标存在就先列出问用户，不要造空链。
7. 参考/导入页不动：frontmatter tags 含"导入"或"排查参考"的页面是参考资料，不参与分拣、不重写、不改格式。
8. 同步更新 `index.md`（对应业务线行的速记链接用 ` · ` 追加到行末；新 Pattern 页补进 20-Patterns 表）；在 `log.md` 记一笔（`## YYYY-MM-DD` 标题，最新在最上、紧跟文件头说明之后）。
9. 最后简要汇报：分拣几条、各归何处（含 frontmatter 修正情况）、几条进待复核（原因）、提炼/更新了哪些 Pattern 页、红线复查发现并脱敏了什么。

纪律：两份资料冲突时并排放置、各自注明出处和日期、留一行提醒等人工裁决，不擅自覆盖；拿不准归属的留 `00-Inbox/` 或归公共平台并说明；只处理本次待分拣文件，不重编全库。全程中文。不要调用 Columbo 服务，不要改动知识库根目录以外的任何代码。
